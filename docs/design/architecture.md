# 项目架构

目标是定期生成可解释的投资研究报告。报告说明判断、依据、反证、期限与失效条件，不输出仓位、调仓或自动交易指令。

## 当前内容

| 目录 | 职责 |
|---|---|
| `docs/investment/` | 长期投资框架和方法；不作为当期市场证据 |
| `docs/design/` | 业务流程、实现边界和数据定义 |
| `docs/TODO.md` / `docs/ideas.md` | 已确认工作与尚未排期的研究想法分别维护 |
| `docs/archive/` | 迁移历史快照，不作为当前目录说明 |
| `resources/` | 人工维护的数据源、订阅和资产资料 |
| `resources/legacy/` | 旧参数、日历及 Prompt，仅供参考 |
| `private/` | 凭据和个人资料，不进入 Git |
| `.agent/tmp/` | 临时脚本与检查产物，任务结束后清理 |

## 开始实现时再创建

```text
config/reports/          # 实际启用的数据源、观察窗口、模型与输出配置
prompts/                 # 正式使用的内容任务提示词
templates/               # 报告排版模板
src/invest/
├── cli.py               # 统一命令入口
├── sources/             # 必要的数据获取
├── research/            # 清洗、筛选、计算与证据整理
├── reports/             # 报告流程、生成、校验与渲染
└── llm.py               # LLM 调用
tests/                   # 核心逻辑的最小有效测试
data/                    # 输入快照、中间结果和缓存，不进 Git
reports/                 # 最终报告及生成记录，不进 Git
pyproject.toml           # 开始实现 Python 功能时定义依赖
```

资源目录回答“有哪些资料”，运行配置回答“这份报告实际用哪些资料”。从旧参考中选用规则时明确新口径，不直接把 legacy 文件接成生效配置。Prompt 定义内容任务，模板定义呈现方式。

## 报告链路

先定义一份报告的问题、覆盖资产、频率、观察窗口和样稿，再实现必要的数据链路：

`获取数据 → 整理证据 → 计算与核验 → LLM 归纳 → 报告校验 → 渲染`

数字由程序计算和检查，LLM 使用明确提供的证据组织解释。每个主要判断包含结论、适用期限、驱动、支持证据、反方证据和失效条件，并说明相比上期的变化。信息不足时明确缺项，不用旧材料冒充本期信息。

第一份报告使用具体流程，不预建通用工作流引擎。定时调度按报告需求增加；生成与发布分开，先提供可人工核查的报告，投递功能按需实现。

## 产物与保留范围

```text
reports/<报告类型>/<期次>/
├── report.md            # 阅读正文
├── evidence.json        # 引用证据与必要数据快照
└── manifest.json        # 截止时间、模型、Prompt 版本和生成状态
```

新一期不覆盖旧一期，修订须留记录。证据快照保留支撑结论的最小内容，避免为每份报告复制整个原始数据集。缓存、中间文件和重复下载应有清理条件；不能删掉已发布报告的唯一证据。

校验重点是数据新鲜度、引用完整性、数字一致性及关键缺项。不同报告可以采用不同观察窗口，不能把统一的文件保留天数当作所有报告的证据有效期。
