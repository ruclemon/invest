# 数据定义与元数据说明

本项目保存参考定义，不建立数据库或可执行 schema。空值、身份和时间语义应先明确，再考虑将来是否实现。

## 资料文件

| 文件 | 内容与边界 |
|---|---|
| [sources.json](../../resources/sources.json) | 行情服务资料、RSS 和公众号订阅；`legacy_enabled` 仅表示旧配置启停状态 |
| [assets.json](../../resources/assets.json) | 资产分类、别名、关注列表、观点映射和搜索关键词；旧命名空间分别保留 |
| [etf_mapping.json](../../resources/etf_mapping.json) | ETF 显式映射、行业提示、排除规则、发行商资料 |
| [research_parameters.json](../../resources/legacy/research_parameters.json) | 旧评分、策略、作者权重、风险和筛选参数，不是生效配置 |
| [calendar.json](../../resources/legacy/calendar.json) | 12 条旧人工日程配置，保留来源链接；不是最新日历，也不包含历史抓取数据 |

各 JSON 的 `sources` 指向旧项目相对路径，`source_root` 仅供追溯。`migrated_on` 是迁移日期，不能当作服务验证或数据更新日期。`status` 明确参考性质。

## 资产身份

- `asset_class`：研究分类，如黄金、美国国债；不一定可直接交易。
- `code` / `proxy_symbol`：观察或交易标的。ETF 只是某资产类别的代理，不能无条件等同。
- `price_source_id`：行情源识别符，可能与研究代码不同。
- `asset_id`：旧文章和 Prompt 使用的身份。保留来源命名，不假设各系统完全一致。
- `opinion_asset_classes`：一个标的关联的观点类别，可为多项。
- `industry_bucket`：行业观察分类，与 broad 资产类别分开。
- `hard` / `soft`：旧资产别名的强、弱匹配词。弱命中不能独立证明金融资产相关性。

旧资料同时出现 `AU/GC/GOLD`、`CL/WTI/CRUDE_OIL`、`BTC/BITCOIN` 等命名。`assets.json` 保留旧归一规则和别名原貌；不直接合并所有标签，因为存在主题、资产、标的三种不同粒度。Prompt 中旧资产集合不完全等同于注册表。

关注列表由旧主配置显式指向 `config/watchlists.example.json`，共 28 项。这证明配置引用关系，不证明每个标的实际交易过。旧到期合约不能被当成当前可交易合约。连续价格标识、基础品种和具体月份合约必须分开。

## 研究记录的最小字段

| 对象 | 应保留字段 |
|---|---|
| 信息来源 | 标识、名称、用途、入口、覆盖范围、认证引用、使用状态、验证日期 |
| 文章证据 | 标识、标题、来源、作者、URL、发布时间、采集时间、文章类别、引用内容 |
| 逐资产观点 | 文章标识、资产身份、原文叫法、立场、理由、时间窗口、分数口径 |
| 资产判断 | 分析时点、资产类别、期限、方向、证据、反证、风险、失效条件 |
| 策略研究 | 类型、各条腿的作用、风险暴露、收益来源、成立与失效条件；不含仓位或下单字段 |
| 日历事件 | 事件标识、国家/市场、类别、日期、时区、日期精度、是否估计、来源 |

这些是文档约定，不要求现在生成记录文件。未来扩展时先证明字段有用途，不照搬旧系统的完整 schema。

## 行情与口径

价格记录至少区分交易日期、市场、币种、复权方式及 OHLC；成交量需声明股、手、币等单位。成交金额与成交量不能混用，OI 是持仓量，不能由成交量替代。

资金费率记录应注明计息事件和间隔。旧日频设计保留 `funding_rate`（当日事件均值）、`funding_events_count` 和 `funding_rate_annualized_est`。日均费率不等于当日累计成本，年化估计需要说明所用事件数和观察窗口，不能固定假设所有产品每天结算三次。

ETF 的 `listed/pending/issuing` 分别表示已上市、待上市和发行中。AUM 与份额是不同量；跨币种汇总须记录汇率及日期。旧固定换算系数没有作为当前汇率迁入。

## 时间与缺失值

时间戳保存时区或 UTC，业务日期注明对应市场。不要用采集日期覆盖发布日期，也不要用公告日期代替生效日期。旧方案按“主要资产”推导市场时区，可能与后续取消 `strongest_asset` 的设计冲突；保留明确时区原则，不继承猜测规则。

未知值使用空值并注明原因；零只代表真实数值为零。零篇观点、意见抵消和缺少文章获取能力属于不同状态。样本不足、部分市场覆盖和过期日期都应显式说明。

## 已保留的冲突

| 冲突 | 迁移处理 |
|---|---|
| 观点半衰期草案 5 天、配置 7 天 | 两者注明来源；参数参考保存配置值 |
| 顶层权重与信号内部权重并存 | 分别保存，不自行合成为新评分公式 |
| 文章总分与逐资产分数 | 保留演进说明，使用时按资产辨别立场 |
| 资产选择按观点强度或讨论篇幅 | 保留旧 Prompt 原文，未设定新规则 |
| 日历设计有 `manual > schedule > window` 和 `schedule > override > window` 两种顺序 | 不选定新优先级，要求核对实际来源后解释冲突 |
| 旧 report-first 草案允许 fallback，后期规则要求 fail-soon | 新文档保留证据不足时停止正式结论的原则，旧降级实现不迁入 |
